| 3 | Memory, measured locally from the container's cgroup `memory.peak` (66 MB, close to the board's 62 MB). Most of it was one 8-byte name hash per record (26 MB plus vector slack). Names come from a pool of 100,000 values, so each distinct name now takes a slot in one table shared by all threads (compare-and-swap on the key) and every group keeps a bitset over the slots; the arrays are calloc'd so only the pages actually used count. Peak 66 MB -> 15 MB. The cost is time: each record now makes two random accesses into shared tables, about 35% slower locally. A first version also kept a compact id per name (one more access, about 55% slower); using the slot as the id removed that. | 5 | Dropped the separate pass that counted every quote byte to find safe split points. Spec 2.2 guarantees, for every seed, that ids are [1-9][0-9]* and notes are lowercase words, so a newline inside a quoted note is followed by a lowercase letter or a quote and a real record boundary by a digit or a byte order mark; I confirmed this on the full, sample and tiny data (392,275 in-quote newlines followed by a lowercase letter, 12,438 by a quote, none by a digit or BOM). Each thread finds its first record by that rule and the parse then checks that every thread stopped exactly where the next one started; if not, the old exact quote-parity method runs instead (tested by forcing it: identical hashes on full and sample). Best-of-9 locally: about 3-5% faster. | run-cf6fd7ffe7d7 (commit f496972) | 0.0633 | 16 | 68.14 |
